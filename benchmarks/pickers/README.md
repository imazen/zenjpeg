# zenjpeg picker code-heuristics

Interpretable, zero-load CART pickers for the zenjpeg lossy encoder config space, generated by the 2026-06-28 dual-model fan-out. The accurate MLP peer is documented here but not committed (see "Why no MLP .bin").

## What's here

- `zenjpeg_lossy_cart_zensim_2026-06-28.rs` — picker fit against zensim quality.
- `zenjpeg_lossy_cart_ssim2_2026-06-28.rs` — picker fit against SSIMULACRA2.

Each file is a standalone, auto-generated decision tree: `pick_zenjpeg_lossy_heuristic(feats: &[f32], zq: f32) -> u16` returns a sweep-cell id (an index into the dump's `cell_labels`) from the 469 zenanalyze image features and a target quality `zq` in 0..100. No model file, no runtime, no dependencies — just nested f64 comparisons that match sklearn exactly. Each file also carries a `main()` that byte-exact-verifies the tree against the `*_cases.bin` fixture on R2. These are reference artifacts; they are not wired into the crate build.

## Two pickers, two roles

CART is the interpretable no-load code-heuristic: a hard decision tree compiled to branches, with nothing to ship but source. The MLP is the accurate ZNPR peer: a small (~214 KB f16) net that picks more sharply but needs the model file plus the zenpredict runtime.

## Measured overhead

Val mean RD overhead vs the per-row reachable oracle (imazen-26 corpus, origin even/odd split, held-out validation; lower is better):

| picker | metric | val mean overhead | notes |
|---|---|---|---|
| CART (committed)     | zensim | 16.4% | depth-6, 63 leaves |
| CART (committed)     | ssim2  | 17.2% | depth-6, 63 leaves |
| MLP (not committed)  | zensim | 6.53% | bake clean |
| MLP (not committed)  | ssim2  | 8.62% | bake refused, forced --allow-unsafe |

CART and MLP overheads come from different fan-out stages (cart_analysis's depth-6 tree over the 54-cell space vs the train_hybrid byte-regression student), so read the gap as indicative of the interpretability cost, not a strict head-to-head. For reference, the per-cell GBDT teacher in the CART's own dump scores 14.9% (zensim) / 17.2% (ssim2) — the committed CART tracks it closely.

## Why no MLP .bin

The MLP ZNPR bakes on R2 are not committed. Six of the seven dual-model bakes (zenjpeg ssim2 among them) failed the bake-time safety gate and were only produced by forcing `--allow-unsafe` past a `BAKE REFUSED` — zenjpeg ssim2 had a WORST_ROW at 308% RD overhead. Shipping an `--allow-unsafe` bake is what the picker program forbids. Their fate is pending a deploy-mode (top-K-verify) gate decision in the main session; until that lands, only the CARTs — which have no bake gate — are committed. (zenjpeg zensim was the one clean bake, but it is held with its sibling pending the same decision.)

## Provenance

- Source: `s3://zentrain/dualmodel-2026-06-28/zenjpeg_lossy/picker_tree_ab/zenjpeg_lossy_cart_heuristic.rs` (zensim) and `.../zenjpeg_lossy__ssim2/...` (ssim2). Copied verbatim, renamed.
- Generator: `zenmetrics/scripts/train/cart_analysis.py`, depth swept 3..16, depth-6 codegen'd.
- Split: imazen-26 origin even/odd (`zenmetrics/scripts/picker/origin_split.py`) — train even origins, val {1,3,5}, test {7,9}; no rendition leakage.
- Cells: 54 zenjpeg lossy configs. The id->config table is the dump `cell_labels` in `zenjpeg_lossy_meta.json` (inside `dump_zenjpeg_lossy_val.tar` on R2).
- Dominant split features (GBDT permutation importance): target quality, min/max dimension, pixel count, laplacian variance.

## Regenerating

```
# fetch and extract a dump tar from R2, then:
python3 zenmetrics/scripts/train/cart_analysis.py \
  --dump-dir <extracted>/val --codec-tag zenjpeg_lossy --eval-split val \
  --codegen-depth 6 --codegen-out zenjpeg_lossy_cart.rs
```
